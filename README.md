# 2du

A local-first Expo workspace for tasks, notes, thoughts, and multiple calendars. Runs on iOS, Android, and responsive desktop/mobile web.

```sh
bun install
bun start           # Expo development
bun run web         # web development, localhost:8081
bun run android
bun run ios         # requires macOS/Xcode
bun run check
bun test
```

Quest is the default theme, inspired by autismaxer.quest: warm black, ivory type, moss and plum accents. Silver and Gold remain in Settings. Local SQLite data is migrated without replacing existing tasks/notes. Tasks can be assigned to named/color-coded calendars, filtered together or individually, and viewed by day/week/month. Notes support Markdown and pinning.

For optional cross-device sync: [server setup](docs/SERVER.md). For external AI agents: [REST API](docs/AGENT-API.md).

## Build output

Keep generated files under the ignored `build/` directory:

- `build/out/`: Android APK, AAB, and APK-set downloads or conversions.
- `build/web/`: web export, generated by `bun run build:web`.
- `build/tools/`: local build utilities such as bundletool.

Local Android production build:

```sh
mkdir -p build/out
eas build --profile production --platform android --local --output build/out/2du-1.0.1.aab
./apk.sh # Newest .aab (build/out/ or root build-*.aab) -> universal APK; installs if ADB sees a device.
```

For an Android update, keep package `com.hyp3.x2du` and the original signing key. EAS manages the Android version code remotely and increments it for production builds. Install updates over the existing app to retain its local data.

## Web deployment

```sh
bun run build:web
bun run serve:web   # http://localhost:8080
```

To build and upload in one step, put the destination in `.env.deploy` (ignored by git) and run the script. Static files are read per request, so `server/web.ts` needs no restart:

```sh
DEPLOY_TARGET=user@host:/path/to/2du/build/web   # files here that aren't in the build are deleted
DEPLOY_URL=https://2du.example.com               # optional, confirms the live build afterwards
```

```sh
./deploy-web.sh --dry-run   # list changes, upload nothing
./deploy-web.sh
```

The bundled static server sets the headers required by expo-sqlite's web worker. Keep one 2du tab open per browser profile: the local SQLite file is locked while that tab is open. If another tab cannot start, close the first one and use **Retry**; do not clear browser storage. Use HTTPS or localhost. With another host, serve `.wasm` as `application/wasm` and set these on every response:

```http
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

SQLite web requires SharedArrayBuffer and a secure browser context (HTTPS or localhost). Use HTTPS for deployment; a plain LAN IP over HTTP will not work for web SQLite. The Metro development server already sets these headers. Storage stays in the browser's origin; changing domains does not carry local data—use sync or JSON export/import. Clearing browser site data deletes the local workspace.

### Installable app and offline use

The production web build is an installable PWA. After the first visit it opens from a local cache, with or without a network, and sync catches up in the background. Service workers need HTTPS or localhost, and are off in development.

Always build with `bun run build:web`: `scripts/precache.ts` writes the file list into `sw.js` after the export, and the service worker fails to install without that step. A new deploy downloads in the background and takes over on the next launch, so an open app is never interrupted. Serve `sw.js` without long-lived caching. The installed app and a browser tab share the same SQLite lock, so only one can be open at a time.

In Settings → Sync, enter the sync server origin and credentials. On first use create an account if the server permits registration; other devices sign in. Sync runs while the app is open. Generate revocable read-only or read/write keys for agents; no AI provider account is required by 2du.

Native reminder scheduling stays device-local. New native dependencies require rebuilding your development/production client. File, font, and sharing packages are aligned with Expo SDK 54. Test a release build on your physical devices before distributing.
